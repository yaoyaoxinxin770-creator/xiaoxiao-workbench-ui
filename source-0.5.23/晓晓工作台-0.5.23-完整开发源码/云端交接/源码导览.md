# 源码导览

## 实际结构

- desktop-app/main.js：Electron 主进程、IPC与本机HTTP服务、渠道服务装配。
- desktop-app/preload.js：桌面桥接接口；前端接口位于 infinite-canvas/web/src/services/api/workbench.ts。
- infinite-canvas/web：当前实际主界面；Next.js App Router、React、TypeScript、Ant Design、Tailwind、Zustand。
- infinite-canvas/{handler,service,repository,model,router,config,middleware}：上游Go后端源码；Go module见go.mod。
- jimeng-canvas-extension：解析器与旧场景/页面执行器兼容代码，仍有共用测试和资源。当前主界面不要误判为 workbench.html。
- desktop-app/dreamina-*.js：即梦CLI、账号、目标画布、草稿、结果、素材缓存及补帧等服务。
- desktop-app/pippit-*.js：小云雀CLI与官网会话、节点准备、生成和回传；pippit-canvas-runtime/scripts保留CLI适配脚本。
- desktop-app/oiioii-service.js、oiioii-runner.cjs：Oii调用与结果处理。
- desktop-app/{asset-store,project-assets,project-library,local-asset-links,video-studio-files}.js：资产、项目、原文件引用与本地结果管理。
- desktop-app/workbench-storage.js、workbench-window.js、managed-runtime.js、runtime-supervisor.cjs：F盘数据位置、窗口托盘和子进程生命周期。
- infinite-canvas/web/src/app/api/codex-agent：Agent请求/停止/设置路由；src/lib/agent-settings.ts负责本机配置保存。该Agent的DPAPI密钥与一般画布通道的浏览器配置不是同一机制，勿混为一谈。

## 生成链路

前端收集本组正文、参数与素材 → 桌面IPC/服务 → 按原账号与画布准备节点/素材并校验 → 按任务冻结的创作模式处理扣费确认 → 查询原任务 → 下载/保存结果并回传原项目。

不能只改前端显示便声称素材已完整提交，也不能凭相似名称收取其他任务结果。账号、画布、项目、原提交ID和素材快照是需要保留的归属信息。

## 旧文档与上游二进制的区别

desktop-app/README.md、jimeng-canvas-extension/README.md及infinite-canvas/docs含长历史，部分条目已经被新规则替代；按需检索，不当作最新待办表自动执行。

本机安装使用的Go服务是官方Windows二进制，来源见desktop-app/infinite-canvas-runtime/NOTICE.md与ORIGIN.json。官方构建存在覆盖层，不能声称包内公开Go源码与安装二进制逐字对应。修改Go后台后，需要在本机整合时核对构建差异和真实兼容性。
