# 云端开发与验证

## 先明确环境

本包提供源码与模拟测试，未携带正式运行环境。云端可以开发前后端、解析/匹配、任务服务和CLI适配逻辑；Windows EXE、DPAPI、托盘、系统通知、VBS、真实CLI授权及官网会话需要回本机验收。不要为适应Linux开发环境而删掉或替换这些产品能力。

建议使用Node 22或兼容当前依赖和import.meta.dirname的更新版本；Go版本以各go.mod为准（主后端go1.25.0）；完整桥接构建还需要Bun和Go。Node/npm/Electron等精确依赖以现有锁文件为准，不要顺手升级。

## 前端开发

在 infinite-canvas/web 内：

~~~sh
npm ci
npm run dev
~~~

开发服务默认端口3000。部分页面依赖本机desktopBridge或Go服务，云端没有用户项目时应使用独立design-preview和虚构数据，不得用模拟数据覆盖原API/store。

类型与前端构建可在该目录分别执行：

~~~sh
npx tsc --noEmit
npx next build --webpack
~~~

现有next.config.ts设置了ignoreBuildErrors=true，所以构建成功不能替代单独的类型检查。npm run build原脚本还调用Bun桥接构建；所需canvas-agent/scripts和native/comfy-bridge源码已包含，排除的3个桥接可执行文件可按现有脚本生成。具体运行结果由执行者如实记录，不在此预先承诺成功。

## 桌面模块与模拟测试

在desktop-app用锁文件安装依赖。只检查纯Node模块时可以npm ci --ignore-scripts避免下载Electron二进制；这不代表已具备Electron界面测试环境。

项目现有测试通过execute替身模拟CLI。可从独立测试入手，例如在解压根目录执行：

~~~sh
node jimeng-canvas-extension/test-analyzer.mjs
node desktop-app/test-dreamina-canvas-service.mjs
~~~

这些是入口示例，仍需按实际改动选择关联用例，遇到平台依赖或失败如实记录；不能把两项示例通过写成整个应用通过。本次导出未运行这两项示例。

个人版完整入口：

~~~sh
node desktop-app/run-tests.cjs
~~~

当前该入口发现166项个人版test-*.mjs。test-video-share.mjs和test-video-share-package.mjs明确范围排除；其源码保留供参考，不执行、不计通过。当前全量入口会把SKIP标记视为失败，不能改入口掩盖跳过项。

云端缺少Windows界面、官方运行时或凭据时，部分测试不能完成。这要作为环境限制列出，不能篡改断言或用模拟CLI冒充真实官网。

## Go后端

相关源码改动时，可在infinite-canvas内按影响范围运行go test，跨模块核心改动需要扩大验证，并回本机执行根规则要求的完整个人版回归。

本机Go程序是官方二进制，来源与公开源码差异见源码导览；本包不含该二进制、数据库或runtime-settings.json。不要把云端编译结果直接替换用户本机程序后宣称兼容已完成。

## 本机打包链路（供交接，不在云端直接安装）

- 锁文件安装前端/桌面依赖；根据任务需要准备现有固定版本的官方运行时。
- 在源码根运行node desktop-app/build-native-workbench.cjs，更新public/xiaoxiao兼容资源。
- 在infinite-canvas/web执行类型检查和next build --webpack。
- 根目录运行node desktop-app/prepare-native-runtime.cjs准备Next standalone。
- 在Windows用现有Electron构建配置打包个人版，执行成品一致性与隔离启动检查。
- 本机AI比较基线及期间修改，按需备份程序和数据，确认正式程序退出后部署，再使用原VBS打开。

此链路只是说明，不代表本轮已经执行。本轮仅导出源码和验证压缩包完整性，没有应用测试、编译、安装或扣费生成。
