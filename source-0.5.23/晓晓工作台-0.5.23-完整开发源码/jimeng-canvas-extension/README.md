# 小云雀工作台连接器（0.20.9）

当前插件只连接小云雀画布，使用官网可见按钮发送；即梦 CLI 不依赖此插件。目录名沿用历史项目路径，浏览器显示名称已经独立。

保持桌面工作台运行，在已授权的 Chrome 中打开本项目已保存的小云雀画布。首次安装或升级后启用一次，之后页面打开、切换、浏览器后台休眠和工作台重新启动都会自动恢复连接；插件图标绿点表示已有画布连接，点击图标可查看状态。不同浏览器资料不要同时打开同一个目标画布，以免误选账号。

当前 manifest 不再注入即梦脚本。下方旧版即梦说明仅保留为历史源码维护资料，不是小云雀连接的操作步骤。

# 即梦画布批量投放工作台（浏览器扩展）

当前桥接执行器版本：v0.18.9。工作台（`workbench.html`）负责整稿解析、提示词编辑、资产匹配、逐视频形象选择、音频绑定、替换和队列状态；本扩展在工作台路径中只承担桥接和执行器职责：确认同一个即梦画布标签页、分块转运已选文件、在画布输入框中写入工作台已经确定的内容、插入真实素材 @、点击发送并回报结果。扩展内旧的 `sidepanel.js` / `calibration.js` 入口保留作兼容资料，不再作为当前工作台的数据来源或功能开发入口。

工作台更新提示词和资产规则时，不需要改扩展的旧业务库。只有桥接协议或即梦页面执行器选择器发生变化时，才需要重新加载本扩展并刷新画布标签。扩展不会读取 Cookie 或调用即梦私有接口。

v0.18.7。角色音频从“跟在人物主体/人物图 @ 后面”调整为“每个视频提示词最前面专门声明音色并 @ 音频”。实现上先上传本批绑定音频，再按每个视频的出场人物和音频绑定关系生成音色前置行与真实音频芯片；插入前置行时同步平移原人物/场景锁定偏移，避免新增文本把后续 @ 位置推错。没有绑定音频的角色不会生成空声明，未出现在该视频的人物音频也不会误加到该视频。

v0.18.1。真机复现：首次上传后即梦只显示折叠的叠放卡片，分类 tablist 不会自动挂载。上传前及上传确认期间，现在会先点击当前输入区的专用素材展开入口，再读取真实分类计数；不会用叠放卡片数量推断附件，也不会补投或自动发送无法确认的附件。

v0.18.0。真机取证发现 `reference-group-*` 会同时匹配附件容器及其背景、悬停层和内容层，`--reference-count` 在零附件时也恒为 1，因此二者没有可靠的附件数量语义。本版本弃用这些哈希类和 CSS 变量，改读当前编辑器范围内第一个 `[role="tablist"]` 的图片、视频、音频、文档分类计数；页面为虚拟滚动同时渲染两份相同 tablist 时只取第一份，避免重复计数。

v0.18.0。附件卡片可能先于分类 tablist 渲染，因此“部分增加后稳定 8 秒”不能证明上传结束。本版本始终等待相关分类数量全部到齐或完整 30 秒观察窗结束；首次上传前没有 tablist 视为合法零基线，后续音频使用本任务已确认的分类快照，避免把暂时不可读误当成零并重复投递。

v0.18.0。分类数量只能证明某类附件少了几个，不能证明具体缺少哪个文件。本版本不再按数组尾部推断缺失文件名，也不再据此跳过场景图片 `@`；图片数量不足会在发送前明确失败且不自动补投，因为在没有文件身份信号时补投可能上传重复图片。

v0.17.5。额外图片未手填“绑定角色”时，改用整稿已解析的人物名单反向匹配工作台名称或文件名 stem：归一化后的角色名是 stem 前缀即可命中，多项命中取最长角色名，无命中仍回退完整 stem。手填绑定继续优先，图片在下拉与 @ 中仍保留完整显示名，角色归属与素材版本名互不混用。

v0.17.5。附件上传链路增加临时结构化诊断日志，记录所选 file input 的 accept、附件数量各来源与中间值、数量分区依据及推断文件名、每轮补投前后计数和耗时，用于区分“页面未接收文件”与“页面已接收但 attachmentCount 未数到”。本次只加日志，不改变上传、确认或重试行为；完成真机定性后可精简这些埋点。

v0.17.4。图片额外附件在“绑定角色”留空时，会按工作台名称自动推断角色；手填绑定仍拥有最高优先级。这样图片与音频在同一附件面板里遵循一致的默认绑定口径，同时保留一张图片绑定多个角色的明确控制能力，避免仅填写工作台名称后人物卡片仍找不到候选。

v0.17.4。人物来源卡片新增“应用到该角色全部视频”，把当前卡片的主体库或指定额外图选择批量写入该角色每个视频已有的独立选择记录。这样可以减少重复操作，同时不引入覆盖单视频选择的全局默认层；再次批量应用时，结果和逐视频手动选择使用同一套回落与清空语义。

v0.16.6。场景图片自定义名或别名修改后，下面的资产审查卡不会被立刻清空，只会标记为待重新校准，方便先把全部图片改完再统一点击校准刷新。整稿页新增“检测主体库人物并自动跳过不存在项”：会按当前整稿里识别出的人名逐个查询即梦主体库，精确同名存在才保留可勾选；明确不存在的人会在资产审查中置灰并从发送计划排除，可改用额外附件上传参考图。

v0.16.5。扩展侧栏默认打开“整稿 @ 校准模式”，并移除旧的橙色多候选下拉选择区；同名或多候选场景统一在下方逐视频资产审查卡里核对，通过给目标图片设置自定义名或别名完成校准，未自动确定的多候选场景按缺图策略跳过对应图片 @ 后继续发送。超长整稿拆批后，每批含 N 个视频就至少等待 N 分钟，并以画布中新出现的 N 个视频任务卡作为下一批放行条件；这里确认的是“已成功发送并进入排队”，不等待最终渲染完成，任务卡后来生成失败也不影响下一批放行。数量不足时持续核验且不会抢发。整稿页新增按发送批次展示的资产检查，人物可逐视频勾选决定是否插入主体 @；场景审阅按视频显示独立卡片、匹配状态、识别名称、实际图片路径和预览缩略图。场景候选库支持文件夹与单独选图混合管理、清除全部或勾选清除，并可给每张图设置仅在工作台内生效的匹配/上传主名称及多个匹配别名，不修改磁盘原文件；任一别名命中时仍只上传一次该图片。独立视频模板支持一个【场景与连续状态】内的多分场写法，例如“场景A｜镜头01：深夜，妖管局大楼外景。”会把镜头冒号后的“妖管局大楼外景”识别为场景，A/B/C/D 仅作为分段编号；每个分场分别匹配并插入图片 @。精准校准同时兼容场景和人物直接写在视频标题中的旧格式。主体候选存在但连续 3 次未生成芯片时，会自动拉宽/拉窄即梦右侧对话栏使候选重新排版；主体库明确不存在则跳过。

## 为什么采用扩展

扩展直接运行在已经登录的即梦标签页内，不创建另一套 Playwright 浏览器配置，也不伪造即梦私有接口。它复用当前画布的登录态、主体库和 Agent 模式，通过复制标签逐条投放任务。

当前策略是 **delivery-first（送达优先）**：校准阶段未匹配到的场景或无法生成的图片 `@` 仍按既有策略跳过；已经选择上传的附件必须通过分类数量确认，确认不足会在点击发送前停止。发送箭头点击后若输入框与附件没有清空，工作台会继续执行“暂停白方块→正式发送”，直到页面确认受理或用户主动暂停。若即梦后台已受理但页面回执严重延迟，这一策略可能造成重复生成。

## 安装

1. Chrome 地址栏打开 `chrome://extensions/`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录 `jimeng-canvas-extension`。
5. 固定扩展图标，点击图标打开右侧工作台。

v0.1.3 起扩展会申请 Chrome 的“调试程序”权限，只用于向当前即梦标签的发送箭头派发一次真实鼠标点击。即梦不接受网页脚本的 `element.click()`，因此这项权限是可靠发送所必需的；扩展不会读取网络请求、Cookie 或账号数据。

v0.1.4 起，`@主体` 会先等待主体菜单加载、再输入名称，并在点击候选后验证主体芯片；附件确认直接统计当前输入区的真实素材卡片，兼容即梦新版展开式素材面板。多标签的输入动作会错开 1.5 秒，生成任务仍可并行运行。

v0.2.0 增加“锁定主体”和“锁定图片”：从提示词的 `【出场人物】` 自动识别角色并在对应名字后插入主体芯片；从 `【场景与连续状态】` 的“场景：”行识别场景，在所选文件夹中按文件名匹配图片，上传命中的图片并在对应场景短语后插入图片芯片。

v0.3.0 增加批量提示词智能分组。可直接粘贴一整段模型回复：扩展会提取每个 `plaintext/text/txt/prompt` 或无语言标签代码块中的视频提示词，兼容外层四反引号、内层三反引号的混合格式；标题、YAML 外壳、批次进度和“下一批”说明不会进入发送内容。没有代码围栏时，会按重复出现的 `【项目规格】` 拆分。

场景图匹配优先读取“场景：”行；提示词没有该字段时，会用所选文件夹内的图片文件名在提示词全文中寻找同名场景短语。自动主体只显示在锁定预览中，不会填入“手动补充”文本框；真实 `@` 芯片在投放阶段插入。

v0.3.1 将“提示词已识别”和“锁定校验未通过”分开显示，避免队列尚未加入时误以为识别失败；锁定有问题时，加入按钮会直接显示问题数量。

v0.4.0 改为手动触发识别：粘贴时不运行解析，只有点击“开始识别并加入分组队列”后，才拆分提示词并直接入队。当前工作台取消自动主体/场景图锁定及文件夹匹配，缺少这些字段不会阻止入队。

v0.5.0 增加“队列资产检查”：自动汇总全队列及每个视频的人物、场景，去重后可逐项勾选核对。`场景：`字段属于确定资产；缺少该字段时，从“构图（开镜静态）”首句提取的场景会标记为“候选”，无法可靠判断时明确显示“未识别”。资产检查只供人工核对，不会自动锁定或上传素材。

v0.6.0 恢复可控的主体 `@`：人物资产默认勾选，勾选项会在每条提示词对应人物名后插入真实主体芯片；不在主体库里的群众、群体等名称应先取消勾选。场景仍只供核对，不自动匹配或上传。新增“暂停后续发送”：暂停会立即结束等待计时，并阻止尚未打开的后续任务；已经开始填写或点击发送的当前任务会完成，避免留下无法判断是否已发送的半成品。再次点击开始可继续已暂停任务。

v0.6.1 修复主体候选菜单展开后编辑器光标丢失、只留下空 `@` 的问题：菜单里已有精确主体时直接选择；需要搜索时会先恢复到刚插入的 `@` 后再输入名称。`人群/众人/群演/士兵/侍卫` 等群体资产仍会出现在核对清单中，但默认不参与自动 `@`，可由用户手动改选。

v0.6.2 不再把 `@` 强行插进已经写完的长提示词中间。扩展按正文从前往后逐段写入：每到一个人物名时，先让该名字位于输入框末尾，再生成真实主体芯片，验证成功后继续拼接冒号和后续正文。这规避了即梦在 `名字 @：后续正文` 结构下偶发不弹候选菜单的问题。

v0.7.0 增加“场景图片智能匹配”。识别入队后选择场景文件夹并手动点击匹配按钮，扩展会读取 `场景：/场景A：/场景B：/场景C：`，去掉日夜、内外和镜头说明后匹配文件名。允许包含关系匹配，例如“无云寺.png”可用于“无云寺墙头”和“无云寺外墙”。每条任务只上传实际命中的去重图片，并在每个场景短语后生成真实图片 `@`；未匹配场景会明确显示。

v0.7.1 修复场景图片已上传、候选菜单也随后出现，却被提前报告“候选菜单没有加载”的问题。图片候选最长等待60秒；候选检测不再要求整个卡片完全位于浏览器视口内，兼容长提示词底部向上展开且内部滚动的菜单。

v0.12.4 修复主体候选识别：主体库候选通常带头像（包括 blob 图片），不再因为头像图片而被误判为场景图片；@苏晚等主体可正常精确选择。

v0.12.3 整稿分批的前置词改为按批次动态生成：自动写入本批视频数量和编号列表，并在“现在开始执行任务：”后拼接本批提示词；不会把整稿编号列表错误复用到每一批。

v0.12.2 优化超长整稿分批标签流程：第 1 批直接使用用户当前已打开的画布，只有第 2 批及后续批次才复制新标签。

v0.12.1 延长大画布复制标签的加载等待：标签完整加载最长等待 5 分钟，执行器握手初次等待 1 分钟、刷新后等待 3 分钟；页面仍在加载时不会提前报“复制标签加载超时”。

v0.12.0 增加整稿超长自动分批：若固定前置词加正文超过 20,000 字符，则按“视频编号”整段切分，不从视频正文中间截断；第 1 批使用当前标签，后续批次复制新标签。单个视频自身超过限制时会明确提示，避免发送半截内容。缺图仍按少图策略跳过并继续发送。

v0.11.9 修复整稿发送的缺图阻断：场景图片上传只被即梦接收部分时，按“少图也发送”策略跳过缺失图片及对应图片 @，继续发送整稿；日志会明确列出缺失文件。标题中的“闪回/回忆/现实”等括号修饰也不再阻断场景匹配。

v0.11.8 修复整稿校准的场景匹配：标题中的“闪回/回忆/现实”等括号修饰不再阻断与场景库文件名的匹配；原始标题仍完整保留，每个视频仍可单独选择同名场景的不同图片。

v0.11.7 整稿校准模式不再按场景名全局复用候选选择；同名场景会按视频标题逐项展示下拉框，可让视频02的陆家客厅和视频03的陆家客厅分别选择不同形态图片。

v0.11.5 的整稿校准模式直接使用当前即梦标签发送一次，不再复制新标签；分组队列模式仍保持逐条复制标签的原有工作流。

投放采用严格串行。每次开始都会处理当前全部待投放任务，不再设置任务条数上限；上一条发送流程返回后，等待默认 30 秒（可设置 30—1800 秒），才复制下一标签。

等待期间每20秒调用一次只读扩展状态 API，防止 Chrome 扩展后台在较长计时中途休眠；该调用不读取页面、账号或即梦数据。

## 使用

1. 在当前 Chrome 标签打开目标即梦画布，确认已经登录并选中 **Agent 模式**。
   开始前输入框必须没有残留文字、主体或附件；扩展会先做只读预检，避免把旧内容复制到所有任务。
2. 在“单条 / 批量提示词”中粘贴单条，或粘贴包含多个提示词代码块的完整回复。粘贴时不会自动分析。
3. 点击“开始识别并加入分组队列”。每个提示词会成为一条独立任务，并按标题分组；同一次粘贴中的完全重复提示词只保留一条。
4. 在“队列资产检查”核对全队列去重清单及每个视频的人物、场景；人物勾选决定是否自动 `@`。
5. 识别入队后，在“队列资产检查”里核对人物。人物默认勾选，勾选代表投放时自动生成真实 `@` 主体芯片；不在即梦主体库中的名称必须取消勾选，否则该条会在点击发送前失败并保留。
6. 场景图使用“选择场景文件夹”，然后点击“识别场景并匹配图片”。检查每条 `场景名→图片名` 以及未匹配警告；文件夹图片只会按任务选择性上传。
7. `@主体（手动补充）`和普通“选择图片/音频”均为可选项；普通附件仍会应用到本次识别出的每一条任务。
8. 点击开始后任务严格串行：上一条确认受理并等待设定秒数，才会打开下一标签。点击“暂停当前重试及后续发送”会终止当前未确认任务的持续重试，并阻止尚未开始的任务；之后可再次点击开始继续状态为“已暂停”的任务。
9. 设置发送间隔（默认 30 秒），点击“顺序复制标签并发送”；当前全部待投放任务都会进入本批次。
10. 出错时展开最底部“运行日志”，复制后用于定位具体失败步骤。

### 整稿 @ 校准模式

1. 点击顶部“整稿 @ 校准模式”，把包含多个 `视频编号…｜场景：…｜人物：…` 标题的完整提示词一次性粘贴进去；扩展不会拆分正文。
2. 选择场景图片文件夹，再点击“校准标题 @ 位置并检查资产”。预览会逐编号列出场景图片匹配、人物名称和标题内计划插入的 `@` 数量。
3. 校准后先在“队列资产检查”中按实际发送批次核对场景，并逐视频勾选需要锁定的人物；勾选的人物才会插入主体 `@`。再点击发送。场景 `@` 只放在标题场景名后，人物 `@` 只放在标题的逐个人名后。
4. 精准模式不会在缺失场景图或必需芯片生成失败时发送残缺内容；请根据日志修正文件名或主体库后重试。

## 状态含义

- `已确认受理`：发送后输入框正文和附件均清空；仅按钮变成白方块不再算确认。
- `持续重试送达`：正式箭头已经点击，但页面尚未清空输入区；工作台会继续尝试，直至确认受理或用户主动暂停。
- `发送前失败`：尚未点击箭头，可以安全地再次启动该任务。

## 已知边界

- 即梦页面类名可能更新；选择器集中在 `content.js` 顶部，便于校准。
- 浏览器扩展不能凭文件路径静默读取任意本地文件，所以附件必须在侧栏中由用户选择；这是浏览器安全限制。
- 人物资产的勾选状态决定是否自动插入主体 `@`；场景图片 `@` 由文件夹匹配结果决定。同一图片可在一条提示词的多个场景短语中重复引用，但只上传一次。触发资产库使用真实 `Shift+2` 键盘事件；若菜单未弹出或页面失焦，会在第 3 次后继续重试，直到成功或用户暂停。只有普通主体在菜单已加载且没有精确同名候选时才跳过。
- 长提示词导致发送框缩小时，工作台会先点击发送框展开。输入 `@` 后 3 秒没有资产菜单，会清理残留并重新 `@`。主体只有在资产库菜单可见、名称确实进入搜索、菜单已结束加载且结果明确无精确同名候选时才会跳过；菜单未弹出、快捷键未触发、页面失焦或候选未加载等暂态故障会继续重试。该规则同样适用于整稿校准中的主体。
- 如果精确主体候选已经存在但连续 3 次点击仍未生成芯片，工作台会真实拖动即梦右侧对话栏分隔线，交替拉宽/拉窄后继续 `@`，用于绕开最右侧候选卡片的点击死区。
- 超长整稿的下一批不再按固定 1 分钟盲发：上一批有 N 个视频时至少等待 N 分钟，再按发送前快照核对画布新增的非失败视频任务卡。未达到 N 个就每 15 秒继续核验，直到齐全或用户主动暂停。
- 已选择上传的图片和音频都必须由附件分类计数确认；数量不足或上传后分类栏始终不可读时会在发送前停止，不会猜测缺失文件或自动补投。校准阶段原本就未匹配到的场景，以及单个图片 `@` 候选失败，仍按既有策略记录并继续。
- 资产场景识别依赖结构化字段；从构图首句得到的只是候选，可能把构图描述误当地点，所以必须人工核对。
- 串行间隔只从上一条页面确认受理后开始计算；正式发送采用每轮最多三次连续尝试，三次后只等待 3 秒确认。仍未清空输入区时会立即开始下一轮送达重试，不会提前进入下一条。
- 标签清理只作用于扩展有记录的自动复制画布，并跨批次累计：前 10 个自动标签会保留；第 11 个建立后，会关闭前面 10 个并保留最新页。源画布和用户原有标签不在删除范围。页面已确认受理后关闭标签通常不会取消即梦服务端的生成任务，但仍应在即梦资产页核对最终结果。
- 新复制标签若继承了可点击的转圈/停止控件，会先在该新标签中停止旧状态；这个清理点击发生在写入提示词之前，不计作正式发送。正式发送只点击向上箭头。
- 如果白方块直到附件和 `@` 插入过程中才出现，工作台会反复点击暂停，直到上箭头恢复；每次点击后都会复核正文和素材没有发生变化，然后立即执行正式发送。
- 按钮从上箭头变成白方块不再算“已确认受理”；只有正文和附件均被即梦清空才算成功。若点击后仍有正文，会继续执行三连发送与 3 秒确认循环；该送达优先策略可能在页面回执延迟时造成重复生成。
- 每个新标签必须先通过执行器握手且版本必须与后台一致。没有接收端或检测到扩展重载前的旧版本时，会在尚未写入任何内容的前提下安全刷新一次，并继续等待；日志会显示“连接新标签 / 恢复新标签 / 新标签已连接”。
- 文件以 Base64 在扩展内部转交，当前限制单文件 80 MB、本批合计 160 MB。超大音频建议拆批。
- 发送阶段会短暂附加到目标标签以派发 `mousePressed + mouseReleased`，随后立即解除；未取得页面清空确认时会再次尝试，因此回执严重延迟可能产生重复生成。

v0.18.6。测试沙箱曾因 `content.js` 新增 `queueMicrotask` 调用而未注入该标准全局，导致使用 `node:vm` 的 10 个核心测试从那次改动后一直在加载阶段失败，实际业务断言没有被执行。本版只补齐测试沙箱的标准全局并统一版本号；这次破窗说明每轮改动后必须跑完整 `test-*.mjs` 才能收工。
- 扩展没有调用或仿造即梦私有接口；接口签名、风控或服务条款变化不会直接破坏这条执行路径。
