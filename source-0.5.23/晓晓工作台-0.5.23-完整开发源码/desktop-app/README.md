# 即梦批量投放工作台（独立桌面版）

当前已加入 CDP 直连入口，默认连接本机 9333；首次使用请阅读 [CDP 直连使用说明](CDP直连使用说明.md)。下面保留的历史说明中，“只通过扩展连接”描述仅适用于原扩展模式。

工作台是提示词、项目资产和执行队列的唯一事实源。Chrome 扩展只作为本机桥接层和画布执行器：它不解析或保存工作台项目，也不决定要发送哪些文本；它只在工作台完成连接握手后，把已确定的任务交给当前登录的即梦画布标签，并把上传/@/发送的结果回传。旧扩展面板仍保留以便兼容旧项目，但当前功能开发只进入工作台。

这是独立 Windows 桌面工作台，不是 Chrome 扩展页面。`main.js` 会启动窗口和本地连接器端口 `127.0.0.1:17842`。

## 启动

在资源管理器中双击项目根目录的 `启动即梦工作台.vbs`。已经打开的旧窗口需要关闭后重新打开，才能加载新界面。`127.0.0.1:8797` 是 Nana H3，并非本工作台。

```powershell
npm install
npm start
```

## 打包便携版

```powershell
npm run dist
```

Chrome MV3 执行器通过以下接口连接：

- `GET /workbench/poll`：领取桌面工作台发出的分镜执行命令
- `POST /workbench/result`：回传上传、校准、发送和失败状态

接口只监听本机回环地址，不对局域网开放。

## 资产工作台（2026-09-06）

本轮只增加素材管理与分镜绑定记录，未接入新的执行桥接。`calibration.js`、`content.js`、`service-worker.js` 未修改。共用 `analyzer.js` 新增纯函数 `matchCharacterPrefix`：角色名最长前缀匹配，并检查版本分隔符；不改变已有函数或调用方。

- 全部、人物、群像、场景、道具、其他、待确认、音频八个分类；支持名称/路径/角色搜索、拖到分类标签调整分类。
- 从资源管理器拖图片到项目资产区时，会按来源路径和文件名自动识别“人物/场景/道具/群像”；例如路径含“道具”“场景”“人物”会进入对应目录。没有可靠线索的图片进入“待确认”，不根据图片内容胡乱猜分类；需要时可在精细管理中改分类。
- 资产区已改为紧凑的粉白网格，缩略图卡片优先显示，避免占满工作区；展开角色版本时仍可拖动单个版本。
- 先粘贴整稿并解析，人物页按角色归组。随机原始文件名不会猜人物，进入待确认；通过精细管理指定显示名、角色、分类及角色音频。同角色多版本点开后再拖具体版本。
- “添加图片”使用系统文件选择框，复制到当前分类的项目子目录；重名会生成新名字，不覆盖原文件。其余操作不复制或移动素材。
- 工作区可按视频组为每个角色选择一个已识别形象，选择写入 `.jimeng/project.json` 的 `segmentCharacterBindings`，执行时生成对应的主体锁定计划；文字替换支持整稿或当前视频组，并直接写回 `.jimeng/draft.txt`。本轮没有新增桌面台到扩展的文件传输桥接，执行仍沿用现有扩展主体库流程。
- 删除区和精细管理的删除按钮均需原生确认框：取消为默认项，说明从磁盘永久删除、无法撤销；确认后清除本资产区保存的分镜和音频引用。
- 在左侧选择分镜，将卡片拖入资产网格下方标明视频编号的区域。只保存关系，不会把新绑定注入现有执行命令。扩展下一轮需实现读取这些配置，本轮不能声称已经生效于投放。
- Windows 原生异步生成 160×160 范围内的 JPEG 预览，进入视口才申请，最多两项并发、80 项内存缓存；渲染器不加载原图。预览不写磁盘、不写 project.json。素材清单实时扫描；本机现有“穿越重逢”10 项素材五次扫描 0.56–1.47ms，127 项测试目录约 3–4ms，无需保存概况缓存。

新增配置字段示例（合并进现有 project.json，保留原字段）：

```json
{
  "assetOverrides": {
    "人物/ChatGPT Image 2026.png": {
      "displayName": "阮乔-常服",
      "category": "characters",
      "role": "阮乔"
    }
  },
  "audioBindings": {"阮乔": "音色/阮乔.wav"},
  "segmentAssetBindings": {
    "video:01:0": {
      "characters": ["人物/ChatGPT Image 2026.png"],
      "scenes": ["场景/大厅.png"],
      "other": []
    }
  }
}
```

分类值为 `characters/groups/scenes/props/other/pending/audio`。分镜键由视频编号和从 0 起的分镜序号组成，同一份整稿重开后保持；重新排序或改编号后需复核绑定。整稿保存在 `.jimeng/draft.txt`，配置只存标记、名字及相对路径，不存图片或 base64。普通工作区保存不会覆盖精细管理刚写入的映射。

## 测试和验收

### 2026-09-07：上下预览破图修复

故障来自预览层共享的 `promptRenderId`：整稿预览的刷新使当前分镜预览尚未完成的图片请求失效。另一个问题是刷新时读取装饰后 DOM 的 `textContent`，把自动显示的 `@` 当成原文再次解析。旧 UI 测试只检查角色标签个数，未检查两处图片是否解码，导致漏检。

现在两个容器各自维护渲染令牌，分镜预览直接读取当前分镜原文。同一路径同时请求的缩略图共用请求；错误时显示“预览不可用”，不显示破图。原稿、发送命令和执行桥接保持原样。

回归测试先在修复前复现失败，再验证上下预览图片同时 `complete && naturalWidth > 0` 且可见，连续刷新不累积 `@`、原文不变、快速切换分镜、编辑/预览切换以及素材失效后的恢复。截图 `output/asset-workspace-verification/two-previews.png` 使用临时灰色测试图片，以便测试不复制用户素材。

在根目录的 cmd.exe 中运行 `node desktop-app\run-tests.cjs`。逐个运行扩展及桌面源目录中的全部 `test-*.mjs`，打印发现数、执行数、失败数和跳过数；`output/` 中是旧版归档，不是当前测试套件。新增 store 测试覆盖分组、持久化、音频、导入防覆盖、删除清理、路径边界；新增 UI 测试用真实 Electron、实际 asset IPC 和临时素材验证交互，文件选择和删除确认由测试替身返回。测试不使用投放接口。Electron 在受限工具沙箱内可能出现子进程 DLL 加载错误，需要在正常 Windows 进程环境运行，不能跳过 UI 测试假报全绿。

验收：
1. 重启桌面工作台，确认首页只显示项目列表；打开自己的项目。
2. 粘贴整稿并解析，切到人物页，检查角色版本分组；随机文件名进入待确认。
3. 打开精细管理，指定随机图的显示名、人物分类和角色，再选角色音频并保存；重新进入项目确认还在。
4. 选择一个分镜，拖入指定人物版本与场景图；切到另一个分镜，确认绑定相互独立。
5. 用一张可丢弃的测试图片试“添加图片”，再拖入删除区；先取消核对文件还在，再确认删除。
6. 点“← 项目”，滚到底确认工作区完全隐藏。

## 原生画布工作台（0.3.0）

infinite-canvas 的 Next/React 应用现在是工作台本体。桌面主窗口直接打开本地原生前端的 /canvas，项目管理 /projects、即梦自动发送 /jimeng 与字字动画 /typetale 均为同一应用中的功能页，不再使用 iframe 或旧场景侧栏。原生画布菜单也提供这些入口。个人工具运行时挂载在用户布局内，切回画布或项目管理时继续执行；切换项目仍受运行状态保护。

原来的队列、分集、素材精细管理、图片和音频绑定、CDP 连接、API/插件/CLI 通道沿用已测试的实现，DOM 与样式限制在个人功能面板内。项目配置仍位于 .jimeng 和 .typetale，最近项目仍使用原用户目录 recent.json。首次启动把旧 file 来源的 jimeng-/typetale- 本地状态保存为用户目录 legacy-workbench-state.json；首次进入个人工具时导入尚不存在的状态，不覆盖已使用的新来源。画布前端固定使用 127.0.0.1:17843，保持 0.2.0 的画布 IndexedDB 来源；后端独立运行在 17845。17842/workbench 重定向原生画布，浏览器中的个人工具复用原本的本机 HTTP 执行接口。

原生画布 API Key 与未登录的画布媒体、项目保存在浏览器来源中，后端数据库不能单独作为完整画布备份；请使用画布库导出。原生 Agent 和 AI 生成需配置相应通道，真实第三方生成费用与浏览器登录仍由原服务决定。验收不提交收费任务。

ComfyUI 的 Windows/Linux 桥接下载附件也随前端提供，由上游 canvas-agent/native/comfy-bridge 的源码构建。上游独立 music 页面尚不存在，因此导航移除空入口，音频创作仍可使用画布中的音频节点和 Agent。

构建：先使用锁文件安装 infinite-canvas/web 的依赖，运行 node desktop-app/build-native-workbench.cjs；再在 web 中执行 next build --webpack；运行 node desktop-app/prepare-native-runtime.cjs；最后在 desktop-app 中执行 electron-builder --win portable。无需在使用者电脑上安装 Bun、Node、Go 或 Docker。前端通过 Electron 的 Node 运行方式启动，官方 Go 二进制仅提供后端服务。

测试：node desktop-app/run-tests.cjs。原生界面测试覆盖画布/Agent/Skill、项目管理、场景归属冲突、素材绑定、实际 IPC、后台任务跨页继续执行、字字动画状态落盘、刷新持久化和外部导航限制。旧算法与存储测试也全部运行；发现任何 SKIP 标记会判定失败。
