### D008 Agent 对话图片不能超过 3MB

**现在**
- 🟢 上传处写死了：单个附件不超过 8MB，图片不超过 3MB（`video/agent-attachments.ts` 的 `readAgentAttachment`）。服务端另有上限，约 11MB 一张、每次最多 6 个附件（`app/api/codex-agent/route.ts`）。
- 🟢 从资产库把图拖给 Agent、或截帧发给 Agent 时，其实已经会自动缩到长边 1024 再发（`codex-agent-panel.tsx` 的 `attachAssetToAgent`）。只有"上传 / 粘贴本地文件"这条路是直接拒绝的。

**🔵 建议**：不再拒绝大图，改成自动压一份小的发给 Agent。
- 任何大小的图片都能加（上限放到 50MB 左右）。超过 3MB 或长边超过 2048 像素时，自动生成一份长边 2048 的副本发给模型，原图不动。
- 提示一句「已自动压缩 18.4MB → 0.9MB，仅用于发给 Agent，原图不变」。
- 为什么不直接把上限调大：视觉模型自己也会把大图缩小再看，传原图只会更慢、更容易超时；而且发过的图会存进对话历史，原图会把历史撑得很大。
- 这份压缩图只给 Agent 看。**把图拖到视频提示词区当垫图时用的是原图**，见 D006。

**❓ 要你定**：发给 Agent 的图压到多大？推荐长边 **2048**，并且把资产库 / 截帧那条路（现在是 1024）也统一成 2048——你常让 Agent 看站位和表情，1024 偏小。如果觉得现在 1024 已经够用，也可以两边都保持 1024，速度更快。

**🟠 待本机核实**：本机 Codex 和 Antigravity 模式下图片落在 F 盘临时目录并在结束后清理（规则 48）；20MB 以上的图读取时界面不卡。

### D011 音频入库名要不要带前缀

**现在**
- 🟢 入库名自动生成为「参考名-台词前 14 个字」，参考名取你启用的那条参考音频或参考形象的名字（`composer-audio-mode.tsx` 的 `computeAutoTitle`）。
- 🟢 「声线归属」也直接取参考名（同文件里的 `snapRole`）。所以你把参考音频改名成一句台词之后，新音频就成了「台词-台词」，声线归属也跟着变成那句台词——你截图里声线归属显示成一句台词，就是这么来的。

**🔵 建议**：一次解决两件事。
1. 「入库名称」旁加一个「前缀」开关，记住你上次的选择：
   - 开：`角色名-台词`
   - 关：只有 `台词`
   - 输入框仍然可以手改，手改后不再自动覆盖（现有行为）。
2. 前缀和声线归属都改成取**参考音频自己所属的角色**，不再取它的标题。这样即使参考音频的名字是一句台词，新音频也会是「女主-新台词」，声线归属是 @女主。
3. 底栏显示一个可点的「声线归属：@女主 ✎」，生成前能改。

**涉及数据**：只影响新生成音频的命名和归属，旧音频不动。旧的参考音频如果没有角色信息，退回现在的做法（取标题里"-"前面那段）。

**❓ 要你定**：开关默认开还是关？推荐默认**开，前缀用角色名**。

**你的情况**

4. 痛点：补漏洞时，自动匹配经常配到后期的衣服。

**现在的匹配顺序**（🟢 `video/prompt-references.ts` 的 `matchPromptAssets`）
1. 你手动绑定过的
2. 编辑区已经挂着、受保护的
3. 资产库里设了「优先」的同名角色图 ← 问题出在这
4. 名字完全一样的
5. 名字最接近的
6. 还有多张分不出 → 提示「多套素材，请选择版本」

第 1 种情况（提示词写全名）走的是第 4 步精确命中，🟢 现在就好用，不动。

**为什么补漏会配错**（从代码推断，🟠 请本机复现确认）
- 「优先」是整个项目只有一份的状态。剧情往后推，你把新衣服设成优先；回头补前面的洞时，优先还指着新衣服。
- 载入一个视频组时（`page.tsx` 的 `loadVideoGroup`）只带上这个组"手动绑定过"的记录，不带它原片实际用过什么，然后按资产库**现在**的状态重新匹配。
- 🟢 现有的「👗 锁装」（`video/components/composer-group-navigation.tsx`）能把当前组的绑定复制到一段区间的组里，但它是一次性复制：之后看不到哪些组锁了什么，也改不了，后来新导入的组不会自动带上。

**🔵 建议：三层，从近到远**

> 先看这个视频自己用过什么 → 再看它所在的桥段 → 最后才看资产库现状。提示词里写明了具体图名的，永远以提示词为准（规则 23）。

- 用哪一版的素材：你点的是具体某条视频（重新编辑、Agent 关联、补漏台里选中的版本）就用那一条；只是载入整组时，用「采用」的那版，没标采用就用最新成功的一版。

### 🔵 建议：补漏台视图

样子见 🟣 设计预览 `01-补漏台.png`。布局参考了之前「方案 B 暗场剪辑台」的骨架（大预览 + 版本条 + 底部时间线），内容按你的补漏流程重排。

**页面四块**
- **中间 放映区**：大画面；下面是镜头条（镜头 01、02、03…，点一下跳过去）和播放控制（逐帧、倍速、截帧、截音频）。
- **底部 时间线**：当前文件夹的视频组按编号排成一条，每格是这个组的「采用版本」。格子上有小标记：⚠ 有洞、🔧 有几条补洞候选、★ 有高光、虚线表示还没生成。相邻两格之间的小菱形是"接缝"。
- **右侧 当前视频**：这一组的全部版本缩略图（原片、补洞候选、生成中的），标记按钮（✔ 采用、★ 高光、✖ 废片、⚠ 待补），备注，以及「去补这个洞」。

底部提示词面板在这个视图里默认收成一条，点「去补这个洞」时自动展开。Agent 侧栏照常可开。

**你怎么用**

*第一步 找洞*
1. 切到「补漏台」，点「▶ 连播」，从头按编号连着放每组的采用版本——相当于在剪映里拼好再播，但不用导出。
2. 看到某个镜头有问题：按 `X`，记下「V4-12 镜头 03」，可以顺手打两个字的备注。
3. 专门查衔接：点「只看接缝」。每个接缝只放上一段最后 2 秒加下一段开头 2 秒，`→` 跳到下一个接缝。几分钟能过完一集。接不上的按 `X`，记成「V4-09 → V4-10 衔接」。
4. 在上一段里暂停到一帧能看清站位的画面，按 `G`，这一帧就记为这个洞的垫图。不选的话默认用上一段的最后一帧。

*第二步 补洞*
5. 在待补清单里点一个洞 →「去补这个洞」：
   - 底部提示词面板展开，载入这一组的提示词和**原片素材**（就是 D003-A、D006 那套）；
   - 垫图那一帧自动截好、存进资产库、挂到参考区；
   - 这次提交自动带「🔧 补洞」标记，不用再去点顶部的补漏洞开关；
   - 要先让 Agent 改提示词的话，点旁边的「发给 Agent」，视频、垫图、你记的备注一起带过去。
6. 像平常一样生成。可以连着处理下一个洞，不用等。

*第三步 挑片*
7. 补洞候选生成完回到同一组，出现在右侧版本条里，带 🔧 标记；待补清单里这个洞显示「候选 3」。
8. 点「上下文试播」：上一段最后 2 秒 → 候选 → 下一段开头 2 秒。按 `[` `]` 切换候选，每次都从同一个位置重放。这一步代替"拖进剪映对比"。
9. 满意的按 `F` 标 ✔ 采用，时间线这一格换成它，这个洞标为已解决。都不满意就再点一次「去补这个洞」。实在不行，挑一条凑合的按 `F`，洞可以保留为"凑合"状态以后再说。

*第四步 收尾*
10. 好看的镜头：播到那里按 `H`。第一次按是「良」，再按变「优」，第三次取消。记到镜号上（靠提示词里的镜头时间段定位；提示词没写镜头的就按当前时间点记）。
11. 高光清单：列出所有 ★，可以只看「优」、连播高光、导出一张表（视频编号、镜号、时间段、等级、备注、文件位置）。
12. 没用的片子按 `D` 标废片。每组版本条上还有一个「未采用的全部标废片」。
13. 「清理废片…」：见下面。
14. 「导出采用清单」：把所有采用版本按顺序存成硬链接分身，文件名带序号（`001_V4-01.mp4`、`002_V4-02.mp4`…），整个文件夹可以直接拖进 Topaz 或剪映。

**快捷键**（光标不在输入框里时生效；🟠 本机核对不和现有的 `Esc` 防卡、`Ctrl+Z` 撤回冲突）

| 键 | 作用 | 键 | 作用 |
| --- | --- | --- | --- |
| `空格` | 播放 / 暂停 | `F` | 采用这一版 |
| `←` `→` | 上一帧 / 下一帧；接缝模式下是上一个 / 下一个接缝 | `H` | 高光：良 → 优 → 取消 |
| `↑` `↓` | 上一组 / 下一组 | `D` | 废片 / 取消废片 |

  - 移入工作台回收站：🟢 现有行为，可恢复，但仍占硬盘。
  - 删除到 Windows 回收站：🔵 新增，清空系统回收站后才真正释放空间，在那之前都能找回。
- 保护：标了 ✔ 采用、★ 高光或收藏的视频，即使同时被标了废片也不会被删，会单独列出来让你处理。
- 删掉文件后，工作台里这条视频的记录留在回收站，显示「文件已清理」，提示词和参数还能看、还能重新编辑。即梦官网上的节点不动。
- 如果某条废片你之前存过硬链接分身，对话框会提示"外面还有 N 个分身"——分身不删的话空间不会释放，这是 Windows 硬链接的特性。

**涉及数据**（都是往已有结构上加字段，旧项目没有这些字段就等于"没标"）

| 新增 | 存在哪 | 说明 |
| --- | --- | --- |
| 采用版本 | 视频组上记一条视频的编号 | 没标时默认取最新一条成功且非废片的，所以不标也能连播 |

| 补洞 | 🟢 现有字段 | 不新增 |

### D009 截取视频里的一段声音当音频参考

**你的场景**：成片里某句台词有问题，想把视频里某一段的声音截出来，交给音频模型单独重新生成；之后你会做一个 skill，专门把台词的情绪和表演写成配音提示词。

- 🟢 没有 ffmpeg，也没有从视频里取声音的功能。

**🔵 建议**
1. 视频详情的播放控制条上加「截音频」（以后补漏台里也有）：

   - 提示词里有镜头时间段的话，可以直接点「截这个镜头」；
   - 「试听所选」确认范围。
2. 填名称（自动给成 `V4-10-镜头02-音`）和声线归属（选角色；能从这个镜头的台词里认出说话人的话自动填）。
3. 两个按钮：
   - 「存入音频库」：进「🎙️ 可引用声源」，以后可以 @ 引用、当参考原声；
   - 「存入并去补台词」：自动切到音频区，把这段声音启用为参考原声，选好「补台词」预设，并把这个镜头在提示词里的原台词填到「台词：」后面，你改成想要的那句就行。
4. 留一个口子给你以后的 skill：音频区加「让 Agent 写配音提示词」，把台词、角色、这个镜头的画面描述发给 Agent，套用你选的技能，结果回填到音频提示词框。🟢 技能库已经有（规则 48），这个按钮可以等你 skill 写好再加。

**涉及数据**：新增的是普通音频资产，多记一条"来自哪条视频的第几秒到第几秒"。原视频不动。

**🟠 待本机核实**

### D012 分镜 + 剧本对照页

**你要的**：类似你截图里那个工具的排法——左边是视频，中间是分镜，右边是剧本；能一键导入分镜视频组，也能一键导入剧本，剧本按分镜自动对上去。具体怎么识别，你会给本机 agent 一份分镜和剧本让它分析。

**现在**
- 🟢 「导入视频组」已有，支持粘贴或导入整份 MD，只取第三部分的视频提示词（`video/video-group-parser.ts` 的 `splitSourceSegments`，规则 19）。
- 🟢 你的提示词表头里已经带着剧本场次，格式类似 `【视频编号V4-10｜剧本4-6（场景名 日/内）后段】`。这是把分镜对到剧本最可靠的线索。
- 🟢 工作台里没有任何"剧本"的概念和存储。
- 🟢 代码里有一套三栏行的骨架组件（`components/storyboard/shot-row-frame.tsx`），目前只用在兼容页面上，本机可以评估能否复用。

**🔵 建议：分镜对照视图**

样子见 🟣 设计预览 `02-分镜对照.png`。

**每个视频组一行，三栏**
- **左 成片**：这一组的采用版本，悬停播放；下面一排小圆点切换版本；✔ ★ ✖ 快捷按钮。没生成的显示虚线框和「载入并创作」。
- **中 分镜**：这一组的提示词（带现有的高亮，默认折叠成几行，可展开）；下面是用到的人物、场景、道具、音频小标签；「重新编辑」「发给 Agent」。
- **右 剧本**：对到这一组的剧本原文，按行显示（场次行、人物行、动作行、台词行）。每行左边一个小点：
  - 绿：分镜里有；
  - 黄：台词和分镜里的不一样（可以点开看差别）；
  - 灰：分镜里没有覆盖到。

**按场次分段**：行与行之间有场次标题（`4-6 咖啡店 日/内 · 2 组 · 剧本覆盖 85%`）。左侧有一个场次目录，点了跳过去。

**两种"对不上"都摆出来**
- 剧本里有、分镜里没有的场次：显示成一行虚线占位「缺分镜」。
- 分镜里有、没对上剧本的组：归到最下面「未对上剧本」，可以手动指定场次。

**导入**
- 工具栏两个按钮：「导入分镜」（就是现有的导入视频组）和「导入剧本」（新增）。
- 导入剧本：粘贴，或选 `.md` `.txt` `.docx` 文件 → 预览识别出的场次和行数 → 确认。

**自动对齐**
1. 先靠表头：提示词表头写了 `剧本4-6` 的组，直接归到 4-6 场。
2. 同一场有多组（前段、后段）时，靠台词：拿每组提示词里的台词去剧本这一场里找相同或相近的句子，按顺序把剧本行切给各组。
3. 对不上的行留在场次标题下「未分配」，你可以选中几行 →「归到 V4-10」。
4. 第 2 步的识别规则由你的本机 agent 根据你给的样本来定。我在实施单里只规定**数据怎么存、界面怎么改、对不上时怎么手动修**，并把"用你的样本跑一遍，自动对上多少、哪些没对上"写成验收项。

**这页还能顺手解决的**
- 审片时直接看到这一段剧本原文，判断"演得对不对"不用另开文档。
- 台词不一致一眼能看到；发现台词错了可以接 D009 去补台词，剧本原句就在旁边。
- 整集有没有漏拍的戏一目了然。

**涉及数据**
- 新增「剧本」：场次（编号、标题）和行（类型、说话人、文字）。按项目保存。
- 新增「对应关系」：哪个视频组对应哪一场的哪几行，区分"自动对上的"和"你手动改的"，重新导入剧本时手动改过的不被覆盖。
- 🔵 剧本文字比较长，建议**单独存一处**，不和视频组、标记放在同一个保存块里。原因：现在每做一次标记都会整块重写那份数据，把长剧本放进去会拖慢所有标记操作（规则 40、41）。
- 剧本只存在你本机。

**❓ 要你定**
1. 这页主要拿来**审片对照**（生成后核对），还是也要在这里**逐组推进生成**（看着剧本一组组发）？推荐先做对照，生成仍用底部提示词面板。
2. 剧本按什么范围导入：整个项目一份（推荐，按场次编号自动分到各集），还是每个剧集文件夹各导一份？
3. 样本：请准备一份分镜和对应的剧本交给本机 agent。**不要传到 GitHub 仓库**，仓库是公开的。

**🟠 待本机核实**
- 你实际的剧本格式（场次标题、△ 动作行、台词行的写法）和分镜表头格式是否稳定，能不能按上面两步对齐。
- `.docx` 剧本的读取（Agent 附件那边已有读 docx 正文的代码，可参考）。
- 一集上百组时滚动流畅，屏幕外的视频不提前加载（规则 40）。
