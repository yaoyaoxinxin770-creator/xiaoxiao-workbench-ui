# D007 角色库里右键单张图可以置顶

## 需求身份

| 项 | 内容 |
| --- | --- |
| 编号 / 标题 | D007 · 恢复资产库右键图片置顶（角色库内的单张图） |
| 资料基线 | 0.5.37 |
| 用户确认 | 2026-11-13，「按推荐」 |
| 确认范围 | 角色库里对单张图提供「置顶此图 / 取消置顶」；同一角色内排序为 优先 → 置顶 → 其他；置顶只影响显示顺序 |
| 批次 / 规模 | 第 1 批 · 小 |

**先做一件事**：用户原话是"资产库的右键图片可以置顶的功能恢复"，没有说具体位置。云端读代码的结论是缺口在"进到某个角色里，右键单张图"。用户回的是「按推荐」，没有单独确认位置。所以**第 1 步是在本机实际右键复核**，结果和下面「现状」不一致就停下来报告，不要继续。

源码路径的读法和「界面手感约定」见 `00-第1-2批总览与交接.md`。

## 用户要达到的结果

用户进到资产库的某个角色（例如"女主"）里，里面有好几套衣服。他想把现在正在用的那套排到最前面。

现在只能点「设为优先」，但"优先"会让自动匹配在整个项目里都选这张图，正是补漏时配错衣服的原因之一。

改完后：右键这张图 →「置顶此图」→ 它排到这个角色的最前面，带 📌 标记。**只改显示顺序，自动匹配不受影响。**

## 现状（读 0.5.37 源码的结论，待本机复核）

| 位置 | 右键菜单里的置顶 | 代码位置 |
| --- | --- | --- |
| 场景、道具、音频、未分类、视频分类里的单张素材 | 有：「置顶场景 / 置顶道具 / …」 | `video/components/local-asset-menu.tsx`，菜单项 `pin-asset` |
| 人物分类的角色目录、分组卡片 | 有：「置顶人物」，置顶整个角色 | 同文件 `pin-role`；`video/components/video-elements.tsx` 角色目录 |

| 角色详情里的同组小图 | 同上，没有 | `video/components/video-elements.tsx`，`hideRolePin={Boolean(selectedRole)}` |

规则 29 当时写的是"角色独立展示库内的单图及其详情变体不再提供**角色**置顶菜单"——去掉的是在角色里面置顶整个角色，这个决定不变。这次加的是另一件事：置顶单张图。

## 交互与界面

样子见 `设计预览/04-第1-2批界面.png`（设计预览，只说明摆法和操作，名称是占位）。

**入口**
- 角色展示页里的图片卡片，右键。
- 角色详情里的同组小图，右键。
- 已禁用的图不提供置顶（它们本来就排在最后的禁用区）。

**菜单**
- 新增一项，放在菜单**第一位**（规则 29：置顶、优先、禁用排在前面）：
  - 未置顶时：`置顶此图`
  - 已置顶时：`取消置顶`
- 其余菜单项的文字和顺序不变。这里仍然不出现「置顶人物」。

**点了之后**

| 时刻 | 界面 |
| --- | --- |
| 点「置顶此图」 | 这张图移到这个角色的图片最前面（在"优先"图之后），卡片短暂高亮闪一下，让用户看到它去了哪——沿用现有的新增素材闪烁效果 |
| 同时 | 卡片上出现 📌，样式和现有置顶角标相同；放在名称旁边，不盖住左上角的勾选框 |
| 同时 | 一条成功提示：`已置顶「工作服」`，提示里带「撤销」，点了立即恢复原位 |
| 点「取消置顶」 | 回到原来的排序位置，📌 消失，提示 `已取消置顶` |

**排序**（默认排序方式下，同一个角色内）

1. 设了「优先」的图，按设优先的先后（规则 29，不变）
2. 置顶的图，后置顶的排更前
3. 其余的图，按现有规则（手动拖拽顺序、序号）

- 可以置顶多张。
- 一张图同时是"优先"和"置顶"时，按"优先"的位置排，📌 照常显示。
- 长按拖拽排序照常可用（规则 30）。置顶的图之间可以拖动调整；拖拽不会把未置顶的图排到置顶图前面——和现在"优先"图的拖拽约束保持一致。
- 筛选弹层里选了"按名称""最近创建"等其他排序方式时：和现有的场景、道具置顶在这些排序下的表现保持一致，不单独发明一套。见「待决定或待实测」。

**和其他功能的关系**
- 不影响自动匹配、@ 引用库里的顺序、优先、禁用。
- 「置顶人物」（整个角色置顶）照常工作，两者互不覆盖：置顶或取消置顶整个角色，不会清掉角色里单张图的置顶。
- 角色封面和左侧头像的取法不改。

**空状态、批量**：无。多选后右键只作用于右键点中的那一张，和现有单张置顶一致。

## 数据与旧项目

| 数据 | 变化 |
| --- | --- |
| 资产的 `metadata` | 新增一个可选字段记录"单图置顶时间"，例如 `elementItemPinnedAt`（数字，时间戳；没有或为 0 表示未置顶）。字段名由本机定，但**必须是新字段** |
| `elementPinnedAt`、`elementRolePinnedAt` | 不读、不写、不改含义。「置顶人物」会把角色下所有图的这两个字段一起改写或清零，所以单图置顶不能复用它们 |
| 旧资产 | 没有新字段 = 未置顶，显示和现在完全一样 |
| 存储位置 | 和资产其他元数据同一处（`stores/use-asset-store.ts`） |
| 本地文件、历史引用、任务 | 无关 |

## 改动范围

| 文件 / 函数 | 现在的行为 | 要改成 |
| --- | --- | --- |
| `video/components/local-asset-menu.tsx` · `LocalAssetMenu` | 人物分类只在未传 `hideRolePin` 时显示「置顶人物」 | 新增一个开关参数表示"这是角色库内的单图"；为真且素材未禁用时，在菜单第一位显示「置顶此图 / 取消置顶」，点击后写新字段、发闪烁事件、弹带撤销的提示 |

注意规则 40：未打开的右键菜单不提前计算整库角色分组。新菜单项只需要当前这张图自己的字段，不要引入分组计算。

## 验收

准备：一个角色下有 5 张图，其中 1 张设了优先。

| 操作 | 应该看到 |
| --- | --- |
| 进入这个角色，右键一张普通图 | 菜单第一项是「置顶此图」；没有「置顶人物」 |
| 点「置顶此图」 | 这张图排到第 2 位（优先图之后）；闪一下；出现 📌；提示「已置顶「…」」带撤销 |
| 点提示里的「撤销」 | 图回到原位，📌 消失 |
| 再置顶另一张 | 后置顶的在前 |
| 右键已置顶的图 | 第一项是「取消置顶」 |
| 重启工作台 | 置顶和顺序都还在 |
| 回到角色目录，对这个角色点「置顶人物」，再「取消置顶」 | 角色里那两张图的 📌 和顺序没有变 |
| 载入一个提示词里写了这个角色名的视频组，开着自动匹配 | 匹配到的图和置顶之前相同（置顶不影响匹配） |
| 对置顶的图长按拖动 | 能在置顶图之间调整；拖不到优先图前面 |
| 右键角色里一张已禁用的图 | 没有置顶项 |
| 场景、道具、音频里右键置顶 | 和改之前一样 |
| 一个 200 张图的角色里连续右键 | 菜单打开不卡 |
| 四套皮肤 | 📌 清楚，不盖住勾选框 |

相关的已有测试入口：`desktop-app/test-asset-organize.mjs`、`test-asset-ui.mjs`、`test-character-variants.mjs`、`test-element-reference-rules.mjs`。建议给第 2 步的排序加一条用例——风险是以后有人把单图置顶并回 `elementPinnedAt`，导致取消「置顶人物」时把单图置顶一起清掉。
