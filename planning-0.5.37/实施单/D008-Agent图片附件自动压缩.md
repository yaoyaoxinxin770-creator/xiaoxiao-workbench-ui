# D008 Agent 对话能发大图：自动压缩后发送

## 需求身份

| 项 | 内容 |
| --- | --- |
| 编号 / 标题 | D008 · Agent 图片附件不再受 3MB 限制 |
| 资料基线 | 0.5.37 |
| 用户确认 | 2026-11-13，「按推荐」 |
| 确认范围 | 大图自动压一份发给 Agent，原图不动；发送用图长边 2048；资产库和截帧那条路也统一成 2048 |
| 批次 / 规模 | 第 1 批 · 小到中 |

源码路径的读法和「界面手感约定」见 `00-第1-2批总览与交接.md`。

## 用户要达到的结果

用户习惯先把图高清再用，一张图常常十几 MB。现在把这样的图拖进 Agent 对话会被直接拒绝："图片附件不得超过 3MB"。

改完后：任何大小的图都能直接拖进、粘贴进或上传到 Agent 对话。工作台自动压一份小的发给模型，原图一个字节都不动。用户不需要先自己去压图。

## 现状（读 0.5.37 源码）

| 环节 | 现在的行为 | 代码位置 |
| --- | --- | --- |
| 上传、拖入、粘贴本地图片 | 单个附件超过 8MB 拒绝；图片超过 3MB 拒绝；只认 PNG、JPEG、WebP；读成一整段数据直接发 | `video/agent-attachments.ts` · `readAgentAttachment` |
| 加入附件 | 当前模型不支持看图时拒绝；每次最多 6 个 | `video/components/codex-agent-panel.tsx` · `addAttachments` |
| 从资产库拖图、右键「发给 Agent 分析」、截帧发给 Agent | 已经会自动缩到长边 1024 再发 | 同文件 · `attachAssetToAgent` |
| 服务端 | 每张图的数据不超过约 11MB；最多 6 个附件；本机 Codex 和 Antigravity 模式把图写成 F 盘临时文件给模型读，结束后清理 | `app/api/codex-agent/route.ts` |
| **对话历史** | 发出去的图**原样整张**跟着会话存进浏览器本地存储的 `xiaoxiao:agent-sessions`；每个项目最多 30 个会话；保存出错时不提示 | 同文件 · `sendInstruction` 里的 `sentImages`、`updateMessages`、`saveSessionsToStorage` |

最后一行是这次必须一起处理的。浏览器本地存储的容量有限，通常只有几 MB 到十 MB。一张 3MB 的图存进去就占掉一大块。**从代码推断**：发过几张图之后，历史会话可能已经存不进去了，而且不会有任何提示，重启后最近的对话就不见了。这一点待本机核实；但不管现在有没有发生，放开图片大小之后一定要处理，否则更容易丢历史。

## 交互与界面

样子见 `设计预览/04-第1-2批界面.png`（设计预览，只说明摆法和操作，名称是占位）。

**1. 接收**

- 入口不变：拖到 Agent 面板、在输入框里粘贴、点附件按钮选择。
- 图片格式不变：PNG、JPEG、WebP。其他格式沿用现有提示。
- 单张原图上限放到 50MB。超过时提示 `这张图超过 50MB，请先缩小后再发：文件名`。
- 文本类附件（txt、md、docx 等）的大小和字数限制不变。
- 每次最多 6 个附件，不变。

**2. 自动压缩**

| 情况 | 处理 |
| --- | --- |
| 文件不超过 3MB，且长边不超过 2048 像素 | 原样发送，不压缩 |
| 文件超过 3MB，或长边超过 2048 像素 | 生成一份发送用的副本：按比例缩到长边 2048，存成 JPEG（质量约 0.9）。有透明区域的图先铺白底 |
| 压完仍超过 3MB（很少见） | 质量降到 0.8；还不行，长边降到 1600 |
| 图片无法解码 | 提示 `这张图读不出来，可能已损坏或格式不对：文件名`，不加入附件 |

- 原文件始终不动。
- 资产库拖入、右键「发给 Agent 分析」、截帧发给 Agent 这条路，长边上限从 1024 改为 2048，和上面用同一个数值。用户常让 Agent 看站位和表情，1024 偏小。

**3. 附件小卡**

输入框上方现有的附件小卡保持原样，增加三点：

- 压缩需要时间时（大图可能几百毫秒），小卡先出现，缩略图位置显示转圈，完成后换成缩略图。期间发送按钮禁用，悬停说明"图片处理中…"。
- 压缩过的图，小卡右下角显示小字 `已压缩`。
- 悬停小卡显示：`原图 18.4MB（5120×2880）→ 发送 0.9MB（2048×1152）`。没压缩的显示 `原图发送 1.2MB（1920×1080）`。

**4. 提示**

- 一次加了几张大图，只弹一条：`3 张大图已自动压缩后发送，原图不变`。
- 没有任何图被压缩时不弹。

**5. 对话历史里只留缩略图**

- 存进历史的每张附图，只保留一张小缩略图（长边约 320 像素）和它的名称、原始尺寸，以及来源资产的编号（如果它来自资产库或截帧）。
- 发送用的那份图只在本次运行期间留在内存里。当次对话里点附图放大，看到的是发送用的那份；重启之后再点，看到的是缩略图，并在图下方标一行小字 `历史缩略图`。
- 用户消息下面的附图缩略图外观不变。

**6. 历史保存失败要让用户知道**

- 保存 Agent 历史时如果出错，弹一条警告，每次启动最多一次：`Agent 历史会话没能保存（本地存储已满），这次的对话重启后可能找不到。可以到历史会话里删掉几个带图的旧会话。`
- 现有的"加载异常时禁止写回"保护不变。

**7. 记下每张图的来源**（给 D006 用，本单只负责记录）

- 每个图片附件在内存里记下它从哪来：资产库或截帧（记资产编号）、本地文件（留着那个文件对象）、粘贴（留着那份原始数据）。
- 存进历史时只保留资产编号。

**空状态、批量、撤销**：无新增。附件小卡上的移除按钮不变。

## 数据与旧项目

| 数据 | 变化 |
| --- | --- |
| 历史消息里的 `sentImages` | 每项从"整张图"改为"缩略图 + 名称 + 原始宽高 + 可选的资产编号"。读取旧记录时，旧格式（只有 `id`、`name`、`dataUrl`）照常显示 |
| `xiaoxiao:agent-sessions` | 结构不变，体积变小 |
| 发送给服务端的内容 | 字段不变，图片换成压缩后的副本 |
| 资产、项目、任务、账号 | 无关 |

**旧会话瘦身**（单独一步，先报告再做）

1. 先只读不写：统计当前 `xiaoxiao:agent-sessions` 的总大小、其中图片占多少、有多少个会话带大图。把数字报告给用户。
2. 用户同意后：先把原始内容完整备份到容量大的地方（工作台数据目录里的文件，或 IndexedDB），确认备份可读。
3. 把旧会话里的大图逐张换成缩略图。全部成功后才写回；任何一步失败就放弃写回，保持原样。
4. 写回后重新读取核对：会话数、每个会话的消息数、文字内容都和备份一致。

如果第 1 步发现历史已经因为容量问题丢过内容，如实告诉用户，不要试图"恢复"不存在的数据。

## 改动范围

| 文件 / 函数 | 现在的行为 | 要改成 |
| --- | --- | --- |
| `video/agent-attachments.ts` · `readAgentAttachment` | 图片超过 3MB 抛错；直接读成整段数据 | 图片走"读取 → 必要时压缩"的新流程，返回发送用数据、缩略图、原始尺寸和大小；8MB 的总限制只对非图片附件生效 |
| 同文件 | — | 新增压缩函数和"长边上限 2048"常量，供下面两处共用 |
| `video/components/codex-agent-panel.tsx` · `addAttachments` | 一次性 `Promise.all` 读完才加入 | 小卡先出现、带处理中状态；合并提示；记录来源 |
| 同文件 · `attachAssetToAgent` | 长边 1024 | 改用同一个常量（2048）；记录资产编号 |
| 同文件 · `sendInstruction` 里组装 `sentImages` | 存整张图 | 存缩略图和元信息；发送用图放进本次运行的内存表 |
| 同文件 · 用户消息下的附图显示与放大 | 用 `dataUrl` | 优先用内存里的发送用图，没有就用缩略图并标注 |
| 同文件 · `saveSessionsToStorage` | 出错静默 | 出错时提示一次并记日志 |
| `app/api/codex-agent/route.ts` | 校验每张图的数据长度 | 不需要改。确认压缩后的图都在现有限制之内 |

不改：模型是否支持看图的判断；附件数量上限；CLI 模式的临时文件位置和清理。

## 规则更新

用户体验通过后修改 `工作台功能保留规则.md` **第 48 条**，在"……均支持粘贴与上传图片（CLI 模式自动将图片落盘为 F 盘临时文件……禁止落盘到 C 盘），图片附件在输入框内显示真实缩略图预览"之后补充：

> 图片附件不设 3MB 上限：单张原图 50MB 以内均可添加，超过 3MB 或长边超过 2048 像素时自动生成长边 2048 的发送用副本，原图不动，附件小卡标注"已压缩"并可悬停查看前后大小；资产库拖入与截帧发给 Agent 同样按长边 2048 处理。对话历史中的附图只保存缩略图与来源信息，不保存整张图；历史保存失败时给出一次明确提示。
