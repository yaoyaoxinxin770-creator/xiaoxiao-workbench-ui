# D003A 原片优先：补漏时不再配到后期的衣服

## 需求身份

| 项 | 内容 |
| --- | --- |
| 编号 / 标题 | D003A · 自动匹配加入「原片优先」 |
| 资料基线 | 0.5.37 |
| 用户确认 | 2026-11-13，「按推荐」 |
| 确认范围 | 只做方案里的 A 层（原片优先）。B 层换装表、C 层 AI 命名排在第 4 批，**不在本单** |
| 批次 / 规模 | 第 2 批 · 中 |

## 用户要达到的结果

剧情里人物会换衣服。用户一口气跑完全集后回头补洞，这时资产库里设成「优先」的已经是后期的衣服。现在载入前面的视频组，自动匹配会把后期的衣服配上去，补出来的片子衣服是错的，用户得一个个手动换回去。

改完后：**一个视频组只要生成过，再对它做自动匹配时，先用它原片实际用过的那张图、那条音频。** 用户什么都不用设置。

四个真实过程：

1. **载入已生成的组来补洞。** 用户从组切换下拉里选 V4-10。参考区挂上的是 V4-10 原片用的粉色睡衣，卡片角上有「原片」小标。资产库当前优先的是工作服，所以参考区下面多一行小字说明这件事，可以一键换成当前的。
2. **粘贴一段新的补洞提示词。** 外面的 AI 给了一段【视频编号V4-10】的新提示词，用户粘贴进来。人物只写了"女主"。匹配到的仍是 V4-10 原片的粉色睡衣。
3. **点「重新匹配」。** 默认按原片重新匹配。
4. **故意想用新衣服重新生成。** 右键「重新匹配」→「按资产库当前重新匹配」，这一组这一次就按资产库现状来。

没生成过的组（第一遍跑的时候），行为和现在完全一样。

## 现状（读 0.5.37 源码）

**匹配顺序**（`video/prompt-references.ts` · `matchPromptAssets`，对提示词里每个要配素材的名字依次判断）

1. 用户手动绑定的（`manual:` 开头的记录）
2. 已挂在编辑区、受保护的（`preserve:asset:` 记录）
3. 资产库里设了「优先」、名字对得上这个角色的 ← 补漏配错就出在这一步
4. 名字完全一样的
5. 名字最接近的
6. 多张分不出 → 提示「多套素材，请选择版本」

**载入视频组**（`video/page.tsx` · `loadVideoGroup`）
- 只带上这个组保存过的绑定，然后调用 `autoMatchPrompt` 按资产库**现在**的状态匹配。
- 组里保存的绑定只来自三种手动操作：手动绑定素材、手动替换参考图、「👗 锁装」。自动匹配选中的图不会存进去。
- 所以原片实际用过什么，载入时完全没被用上。

**重新编辑一条已生成的视频**（`video/page.tsx` · `previewGenerationLog`）
- 会把那条视频的参考图、音频、参考视频、首尾帧全部还原，并用 `restorePromptBindings` 重建绑定（规则 21）。这条路现在就是对的，本单不改它的行为。

**以上是读代码的推断。** 实施第 1 步先在本机复现一次"载入已生成的组却配到当前优先的衣服"，确认原因和这里说的一致。

## 行为规则

### 1. 哪条视频算「原片」

| 情况 | 原片是 |
| --- | --- |
| 用户明确指定了某条视频（点它的「重新编辑」，或 D006 里 Agent 关联的那条） | 那一条 |
| 载入整组、在已载入的组里粘贴或重新匹配 | 组里**最新一条可用的成片**：生成成功、有视频、没进回收站、没标废片（灰底或「× 不可用」） |
| 编辑区没载入任何组，粘贴的提示词带【视频编号】 | 同一项目里编号相同的那个组的最新可用成片。优先找当前文件夹；当前文件夹没有、而别的文件夹里有多个同编号的组时，**不猜**，按没有原片处理 |
| 粘贴的【视频编号】和当前载入的组不一样 | 以粘贴内容里的编号为准去找（和规则 20 提交时按编号归属的原则一致） |
| 组里没有可用成片 | 没有原片，全部按现有规则 |

第 3 批补漏台上线后，"最新一条可用的成片"会改成"标了采用的那条，没有才取最新"。本单留好这个口子即可，不做采用标记。

### 2. 新的匹配顺序

在现有顺序的第 2 步和第 3 步之间插入一层：

1. 用户手动绑定的
2. 已挂在编辑区、受保护的
3. **原片素材里，唯一能对上这个名字的那一个** ← 新增
4. 资产库里设了「优先」的
5. 名字完全一样的
6. 名字最接近的
7. 多张分不出 → 提示

补充规则：

- **提示词写明了别的服装，以提示词为准**（规则 23）。具体两种情况原片层不生效，直接往下走现有规则：
  - 提示词里的名字和某张图的名称或别名完全一致（忽略空格），而那张图不是原片素材；
  - 提示词里的名字带了限定词（括号里的内容，或 `-` 后面的部分），这个限定词出现在同角色另一张图的名字里，却不在原片那张图的名字里。例如原片用的是「女主-粉色睡衣」，提示词写「女主（工作服）」，资产库里有「女主-工作服」——这时不用原片的。
- 原片素材里有两张都对得上同一个名字（一条视频里同一个角色用了两套图）：原片层不做决定，往下走现有规则。
- 用户在这次编辑里手动移除过的素材（规则 27），原片层不会把它加回来。
- 原片那张图现在在资产库里是「禁用」状态：照常沿用（规则 21、27 对历史素材的原则）。
- 原片那张图的原文件找不到了：显示现有的待补卡「原文件失效，请重新定位」，**不能悄悄换成别的图**。用户可以重新定位、手动另选，或改成按资产库当前匹配。
- 两张图同名时，原片层认的是具体哪一张图，不是名字。
- 图片、音频、参考视频、场景都适用同一套规则。
- 只在同一个项目内生效。

### 3. 什么时候生效

- 载入视频组时的自动匹配；
- 粘贴或整段替换提示词触发的自动匹配；
- 点「重新匹配」；
- 提交前的自动补齐。

顶部「自动匹配」开关关着时，载入和粘贴不会自动挂素材（规则 27，不变）；这时点「重新匹配」，仍按原片优先。

### 4. 只挂用得上的

载入整组、粘贴、重新匹配时，原片素材只是"优先候选"：提示词里提到了哪个名字，才挂哪一张。原片里有、但当前提示词没提到的素材不会挂上来。

点「重新编辑」某条视频仍然是把那条视频的素材**全部**还原，这是现有行为，不变。

### 5. 和现有功能的优先关系

- 「👗 锁装」写进组里的绑定属于"手动绑定"，排在原片之前，照常生效。
- 用户在参考区手动替换、手动绑定、从资产库拖入的，都排在原片之前。
- 「优先」排在原片之后——这正是本单的目的。

## 交互与界面

样子见 `设计预览/04-第1-2批界面.png`（设计预览，只说明摆法和操作，名称是占位）。

**1.「原片」角标**

- 参考区里由原片层配上的素材卡，右上角显示一枚小标 `原片`（绿色系，小号字）。
- 鼠标移到这张卡上时小标隐藏，让位给现有的删除按钮。
- 悬停卡片时的说明里加一句：`沿用 V4-10 · 1 生成时用的素材`。
- 卡片上现有的编号、未引用提示、绑定和定位按钮都不动。

**2. 差异提示行**

只在"按原片配的结果"和"按资产库当前会配的结果"不一样时出现。位置在参考素材条下方、提示词输入框上方，单独一行小字：

```
已按原片匹配 2 项，和资产库当前优先的不同：女主（粉色睡衣）、男主（黑大衣）   换成当前的   知道了
```

- 「换成当前的」：把列出的这几项改成资产库当前会配的那张。可按 `Ctrl+Z` 撤回。之后这一组在本次编辑里按资产库当前匹配，直到重新载入。
- 「知道了」：这一组这次编辑不再显示这行。
- 差异消失时这行自动消失。
- 这行出现和消失时，不改变提示词输入框的滚动位置；面板高度的变化计入现有的底部留白计算（规则 11）。
- 列出的项目超过 3 个时显示前 3 个加「等 N 项」。

**3.「重新匹配」按钮**

现在是提示词面板工具栏里的旋转箭头图标（规则 31 要求保持纯图标）。

- 左键：重新匹配，行为不变，只是多了原片这一层。
- 图标右下角加一个很小的下拉角标；**右键**或点角标打开菜单：

  ```
  按原片重新匹配
  按资产库当前重新匹配
  ─────────────
  默认依据　● 原片优先　○ 资产库当前
  ```

- 「按资产库当前重新匹配」只作用于当前这一组这一次编辑。
- 「默认依据」是全局偏好，记住选择；默认「原片优先」。选成「资产库当前」后，整个工作台回到改之前的行为。
- 悬停说明改为：`重新匹配（当前依据：原片优先）· 右键选择依据`。
- 没有原片可用时，「按原片重新匹配」置灰，说明「这一组还没有生成过」。

**4. 粘贴识别的提示**

编辑区没有载入该组、粘贴的提示词带【视频编号】并找到了已生成的组时，弹一条中性提示（一次）：

`已识别为 V4-10，按它的原片素材匹配`

**空状态**：没有原片时，界面和现在完全一样——没有角标、没有提示行、菜单第一项置灰。

**撤销**：载入、粘贴、重新匹配、「换成当前的」造成的参考素材变化，都能用现有的 `Ctrl+Z` / `Ctrl+Y` 撤回和重做（规则 39）。

说明：「重新匹配」按钮所在的工具栏行出现在即梦 CLI、小云雀、Oii 这几种渠道的布局里。原片优先的匹配逻辑对所有渠道生效；右键菜单只需要在有这个按钮的布局里提供。

**两条实现上的提醒**

- 不要直接拿 `restorePromptBindings` 的返回值当作新的绑定。它是为"重新编辑"写的，会从头重建一份绑定，用户在这次编辑里对其他素材做的手动绑定和手动移除会被丢掉。可以借用它"原片素材对上哪个名字"的判断思路，但要和用户的手动操作合并，手动的永远在前。
- 桌面端规划画布节点时，会优先用编辑区已经挂上的素材来解析提示词里的名字（规则 26）。所以只要编辑区挂对了、且同一个角色只挂了一张，桌面端就会得到同一张图。这一点在验收里用「② 仅建节点」实际核对，不要只看编辑区。

不改：`desktop-app/` 下的任何文件；`composer-group-navigation.tsx` 的「👗 锁装」；`restorePromptBindings` 的现有行为；自动匹配开关的含义。

## 验收

准备（在旧项目的副本里）：

- 角色"女主"有两张图：A「女主-粉色睡衣」、B「女主-工作服」。B 设了「优先」。
- 视频组 V10 已生成，原片用的是 A。提示词的【出场人物】里只写"女主"。
- 视频组 V20 还没生成，提示词里也只写"女主"。

**逻辑**（第 2 步的用例）

| 输入 | 应该配到 |
| --- | --- |
| 名字"女主"，原片素材 = A，优先 = B | A |
| 同上，但没有原片 | B（和现在一样） |
| 名字"女主-工作服"（和 B 的名称完全一致），原片 = A | B |
| 名字"女主（工作服）"，原片 = A | B（限定词命中 B，没命中 A） |
| 名字"女主（睡衣）"，原片 = A | A |
| 名字"女主"，原片里同时有 A 和 B | 原片层不决定，按现有规则得到 B 或歧义提示 |
| 名字"女主"，原片 = A，用户手动绑定了 B | B |
| 名字"女主"，原片 = A，用户这次手动移除了 A | 不是 A |
| 名字"女主"，原片 = A，A 被禁用 | A |
| 两张图都叫"女主睡衣"，原片用的是其中第一张 | 第一张 |
| 声音锁定里的"女主"，原片用了音频 X，另有一条优先的音频 Y | X |
| 场景名，原片用了场景图 S1，另有一张优先的同名场景图 S2 | S1 |

**界面和流程**

| 操作 | 应该看到 |
| --- | --- |
| 从组切换下拉载入 V10 | 参考区挂的是 A，右上角有「原片」小标；下面出现差异提示行，写着女主（粉色睡衣） |
| 鼠标移到 A 的卡片上 | 小标让位给删除按钮；说明里有"沿用 V10 · 1 生成时用的素材" |
| 点「换成当前的」 | A 换成 B，小标消失，提示行消失 |
| `Ctrl+Z` | 回到 A，小标回来 |
| 点「知道了」 | 提示行消失，A 不变；切到别的组再切回来（同次审阅），不再出现 |
| 载入 V20 | 挂的是 B；没有小标、没有提示行；和改之前一样 |
| 清空编辑区，粘贴一段【视频编号V10】的新提示词，人物写"女主" | 弹一次「已识别为 V10，按它的原片素材匹配」；挂的是 A |
| 载入 V10 后，把提示词里的"女主"改成"女主-工作服"，点「重新匹配」 | 换成 B，没有小标 |
| 右键「重新匹配」 | 出现菜单；当前依据显示「原片优先」 |
