| 项 | 内容 |

| 编号 / 标题 | D002 · 「直接生成」模式覆盖音频 |
| 资料基线 | 0.5.37 |

| 确认范围 | 两个音频入口都跟随顶部创作方式；③ 不弹确认；①、② 照旧弹确认 |

## 用户要达到的结果

用户把顶部创作方式选成「③ 直接生成」。之后在提示词面板的「音频」区点「开始创作音频」，或者在 Agent 回复里的配音草稿卡片上点生成，**不再弹出「即梦 SeedAudio 1.0 配音生成确认」**，直接提交并开始生成，完成后照常入库。

选「① 确认生成」或「② 仅建节点」时，音频仍然先弹确认，和现在一样。

已确认：③ 不弹；② 仍弹（音频没有"官网手动生成后回传"的流程，只建节点会走进死路）。

## 交互与界面

样子见 `设计预览/04-第1-2批界面.png`（设计预览，只说明摆法和操作，名称是占位）。

**入口不变**：两个按钮的位置、文字都不动。

**1. 按钮旁显示当前会不会确认**

- 仅当当前是「直接生成」时，在「开始创作音频」按钮左边显示一枚小字标签：`直接生成 · 不再确认`。
  - 样式：11 像素、次要文字色、不带底色，和同一行其他小字一致。
  - 悬停说明：`跟随顶部的创作方式。想先确认积分，把创作方式切到「① 确认生成」。`
- ①、② 下不显示这枚标签，保持界面干净。
- Agent 配音草稿卡片的生成按钮旁同样处理。

这样用户在点之前就知道这一下会不会直接扣积分，不靠记忆。

**2. 点击后的反馈（③ 直接生成）**

| 时刻 | 界面 |
| --- | --- |
| 点下去 | 按钮立即进入加载状态，文字「正在提交…」，不可再次点击 |
| 节点建好、拿到报价、已提交生成 | 一条成功提示：`已直接提交配音 · 预计 N 积分 · 入库名「XXX」`；按钮文字变为现有的「正在生成配音…」 |
| 生成完成 | 现有行为：入库、亮起音频分类小红点、结果条可试听和 @ 引用 |

从点下去到提交完成，按钮**全程保持加载状态**，中间不能出现可以再点一次的空隙。

**3. 不能直接提交的情况**

- 即梦没有返回可用的报价（缺失或不是非负整数）：不提交。提示 `即梦暂时无法报价，音频节点已保留，请稍后重试或到画布核对`（和视频遇到同样情况时的说法一致）。
- 积分不足、内容违规等：沿用现有错误文案（规则 33）。
- 其余失败：沿用现有的错误显示。

**4. 模式从哪里取**

- 以顶部创作方式下拉**当前显示的值**为准。不管当前视频渠道是即梦、小云雀还是 Oii，看到什么就按什么。
- 顶部没有显示这个下拉时（旧版即梦，或当前不是这三种 CLI 渠道），音频按「确认生成」处理。
- 切换模式只影响之后的点击，不会把之前停在确认弹窗上的草稿自动提交（规则 32）。

**取消与撤销**：直接生成没有"取消确认"这一步。生成中的音频任务能否取消保持现状，本次不新增。

**不变的底线**：Agent 只给出配音草稿，生成必须是用户自己点按钮（规则 48）。直接生成模式下也不由聊天内容触发生成。

## 数据与旧项目

- 不新增、不修改任何持久化数据。任务结构、入库字段不变。
- 幂等：每次点击生成一个本次专用的任务标识，随提交一起传给桌面端。桌面端 `desktop-app/dreamina-canvas-service.js` 的 `submitAudio` 已经用 `payload.clientTaskId` 组成任务编号并校验内容签名，同一标识重复到达不会产生第二个任务。
- 积分上限仍取即梦返回的报价，传给现有的 `dreaminaConfirm`，和视频走 ③ 时相同（`services/api/dreamina.ts` 的 `confirmDreaminaDraft`）。
- 账号、画布归属逻辑不变。

## 改动范围

| 文件 / 函数 | 现在的行为 | 要改成 | 为什么 |

## 验收

| 操作 | 应该看到 |
| --- | --- |
| 创作方式选 ①，点「开始创作音频」 | 弹确认，和改之前一样；取消则不生成 |
| 创作方式选 ②，点「开始创作音频」 | 弹确认，和改之前一样 |
| 创作方式选 ③ | 「开始创作音频」左边出现「直接生成 · 不再确认」 |
| ③ 下点「开始创作音频」（**需当次授权**） | 不弹窗；按钮全程转圈；出现一条成功提示，写明预计积分和入库名；生成完成后音频入库 |
| ③ 下快速连点两次（**需当次授权**） | 只生成一条音频，只扣一次积分 |
| ③ 下，Agent 配音草稿卡片点生成（**需当次授权**） | 同样不弹窗、同样的提示 |
| 当前视频渠道切到小云雀或 Oii，下拉显示 ③，点「开始创作音频」 | 按 ③ 处理，不弹窗 |
| 切到旧版即梦（顶部不显示创作方式下拉），点「开始创作音频」 | 弹确认 |
| 在 ① 下点了生成、停在确认弹窗上，把创作方式切到 ③ | 弹窗里那条不会自动提交；关掉弹窗后它保持未生成 |
| 实际扣的积分 | 等于提示里的预计积分（到即梦官网或积分显示处核对） |
| 积分不足时在 ③ 下点生成 | 显示「积分不足，请充值或更换账号后重试」，不重复提示 |
| 四套皮肤、Agent 侧栏 320 像素 | 标签和按钮不重叠，文字清楚 |

相关的已有测试入口（按 `云端规划/测试入口索引.txt`）：`desktop-app/test-dreamina-generation-modes.mjs`、`test-dreamina-generation-modes-ui.mjs`、`test-dreamina-canvas-service.mjs`。改动后运行这几项。建议新增一条防回退用例：`direct` 模式下音频入口不出现确认弹窗、且重复触发只提交一次——风险是这条路径以后被人改回"总是弹"或漏掉幂等。
